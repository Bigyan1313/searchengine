=========================================
Implementation
=========================================
Language / framework:  Python 3.11 + Flask
Local search engine:   Whoosh 2.7.4 (BM25F ranking, StemmingAnalyzer)
Web search API:        Brave Search API (Bing's API was retired in 2025;
                       Brave is the current standard alternative and serves
                       the same role the assignment describes).
Hosting:               Render.com (free tier) for the Flask app;
                       cs.txstate.edu/~wwj15 for the Part A landing page.

Dataset: lyrics.csv (5,100 songs, 1965–2015). 5,053 documents indexed;
47 rows were skipped for missing/invalid lyrics or year fields.

Indexing (build_index.py):
  - Schema: doc_id, rank, title, artist, year, lyrics.
  - StemmingAnalyzer on text fields so "running" matches "run", etc.
  - Field boosts: title 2.0x, artist 1.5x, lyrics 1.0x.

Query handling (/api/local):
  - MultifieldParser across title/artist/lyrics, OrGroup (any term matches,
    but documents with more matches rank higher).
  - BM25F ranking.
  - KWIC snippets generated by Whoosh's highlight module using
    ContextFragmenter (240-char window) + HtmlFormatter (<mark> tags).

UI:
  - Single page, Google-style layout, toggle between Web and Local modes.
  - Local results show title (clickable), year, rank, artist, and a
    highlighted KWIC snippet. Clicking the title opens a song page in a
    new tab with the full lyrics.
  - Web results show title (clickable to external URL), host, and Brave's
    description as the snippet.

=========================================
Observations
=========================================
- BM25F with field boosts gives noticeably better title matches than the
  default TF-IDF. For "broken heart" the top three results are all songs
  with both terms in the title ("Broken Hearted Me", "Cross My Broken
  Heart", "How Can You Mend a Broken Heart"), which is the intuitive
  ordering.
- The stemming analyzer is the single biggest recall improvement for this
  corpus — without it, "loving" misses ~40% of the matches a human would
  consider relevant.
- Snippet quality depends heavily on ContextFragmenter's surround size.
  60 characters felt like the right balance: enough context to be
  readable, short enough to fit multiple hits on screen.
- The dataset has already been lowercased and stripped of punctuation, so
  the rendered lyrics on the song page read as one long paragraph. Line
  breaks aren't recoverable without re-scraping the original source.
