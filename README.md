# Lyricly — Keyword Search Project

Flask + Whoosh keyword search over web pages (Brave Search API) and a local
corpus of 50 years of pop music lyrics.

## Layout

```
search_project/
├── app.py                  # Flask app: /, /api/web, /api/local, /song/<id>
├── build_index.py          # builds indexdir/ from data/lyrics.csv
├── data/lyrics.csv         # 5,100 songs (Rank, Song, Artist, Year, Lyrics)
├── templates/
│   ├── index.html          # search UI
│   ├── song.html           # full song page
│   └── 404.html
├── static/style.css
├── public_html_index.html  # lightweight landing page for cs.txstate.edu/~wwj15
├── requirements.txt
├── Procfile                # gunicorn entry for Render
├── render.yaml             # Render blueprint
└── .gitignore
```

## Running locally

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python build_index.py              # one-time index build
export BRAVE_API_KEY="your_key"    # needed for web search only
python app.py                      # -> http://localhost:5000
```

## Deploying to Render (free tier)

1. Push this directory to a new GitHub repo.
2. Sign in at render.com with that GitHub account.
3. **New → Blueprint** → select the repo. Render reads `render.yaml`.
4. When prompted, set the `BRAVE_API_KEY` environment variable to your key.
5. First deploy runs `pip install -r requirements.txt && python build_index.py`.
6. After ~2 minutes you get a URL like `https://lyricly-search.onrender.com`.

The free tier sleeps after 15 minutes of inactivity and takes ~30 seconds to
wake up on the next request. That's fine for a class demo.

## Deploying to Railway

1. Push this repo to GitHub.
2. In Railway, create a new project from this GitHub repo.
3. Set environment variable `BRAVE_API_KEY` in Railway project settings.
4. Deploy.

This repo includes `nixpacks.toml`, so Railway will:
- install dependencies with `pip install -r requirements.txt`
- build the Whoosh index via `python build_index.py`
- start with `gunicorn app:app --bind 0.0.0.0:$PORT --workers 2 --timeout 60`

## Hosting the Part A landing page at cs.txstate.edu/~wwj15

1. Edit `public_html_index.html` and replace the Render URL with yours.
2. Rename it to `index.html`.
3. Upload to the TXST Linux server:
   ```bash
   scp index.html wwj15@eros.cs.txstate.edu:~/public_html/
   ssh wwj15@eros.cs.txstate.edu "chmod 755 ~/public_html && chmod 644 ~/public_html/index.html"
   ```
4. Verify at <http://cs.txstate.edu/~wwj15>.

## Implementation notes

- **Ranking:** BM25F (Whoosh default), with field boosts — title 2.0×, artist 1.5×, lyrics 1.0×.
- **Analyzer:** `StemmingAnalyzer` so `loving`, `loved`, and `loves` all match `love`.
- **Snippets:** generated by Whoosh's `highlight` module with a `ContextFragmenter`
  (max 240 chars, 60-char window around hits) and `HtmlFormatter` wrapping matches
  in `<mark>`. See `_make_snippet` / `/api/local` in `app.py`.
- **Query parsing:** `MultifieldParser(["title","artist","lyrics"], group=OrGroup)`
  so any term match counts but more matches score higher.
- **Web search:** straight proxy to Brave's `/res/v1/web/search` endpoint,
  returning title / url / snippet / display-url.
